# 方案选型决策评审（Decision）

> 模板定位：记录方案选型的【决策过程】与结论。可行性依据引用 `02-feasibility.md`，不重复。
> 阶段 A（候选方案分析）：§1-§3 填充，§5-§6 占位待用户（代表 SIG 评审）决策。AI 推荐倾向仅供参考，不代行决策。

## 1. 背景与问题

决策问题：系统预置 CA 按国际/国密算法分组展示并返回证书库版本号，涉及 4 个技术决策点（D1 算法判定 / D2 版本号来源 / D3 IPC 携带 / D4 客户端渲染）的方案选型。
硬约束：海外设备无国密证书时不可展示国密分组；向后兼容旧客户端；不新增跨 uid 越权路径。
技术/经济可行性依据见 `02-feasibility.md`。

## 4. 决策过程记录

- 评审时间 / 参与人：2026-11-13 / 安全子系统证书管理（SDD 实践评审）
- 讨论要点：D1 算法判定是否正式化（cm_x509 vs SM2 OID 启发式）；D2 版本号来源（版本文件 vs RDB vs 编译宏）；D3 IPC 携带（复用消息+可选 tag vs 新增消息码）；D4 渲染（单 List ForEach vs 双 List vs LazyForEach）
- 关键转折 / 争议：D1 维持当前实现 D1-B（SM2 OID 字节匹配，启发式），不升级为 cm_x509——遵循"已有实现能别动则别动"原则，接受 R2 启发式对 PEM 证书的漏判风险作为已知限制；D2/D3/D4 维持当前实现
- 最终决策：D1-B + D2-A + D3-A + D4-A（详见 §5）

## 5. 决策结果与理由

**选定方案：**
- D1-B：SM2 OID 字节匹配（当前实现，不改动）
- D2-A：镜像预置版本文件 `/etc/security/certificates/cert_store_version`
- D3-A：复用 `CM_MSG_GET_CERTIFICATE_LIST` + 可选 CmParamSet tag + 响应尾部追加 `CmCertStoreInfo`
- D4-A：客户端单 List + `ForEach(sysCaItems)` 分组头与条目混排

**理由（事实依据）：** D1/D2/D3/D4 均沿用当前已实现方案，不改动已有代码——向后兼容（旧客户端不传 certAlg 行为不变）、客户端侧已通过 `hvigorw assembleHap` 编译验证 0 error。接受 D1-B 启发式对 PEM 证书的漏判风险（R2）作为已知限制。

**决策者：** 安全子系统证书管理（SDD 实践评审）。

> 无实现差距：决策与当前代码实现一致（D1-B+D2-A+D3-A+D4-A），无需 Phase 1 方案级改动。R2（D1-B 启发式限制）作为已知风险接受，不作为遗留。
